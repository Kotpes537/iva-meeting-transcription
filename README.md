# Транскрибация встреч для Iva

Плагин принимает запись встречи в `.m4a` или `.mp3` из личного чата владельца, отправляет короткие тезисы ответом в Telegram и возвращает `.docx` в тот же чат. Word всегда содержит полный транскрипт с таймингами начала и конца каждой реплики и автоматическими метками спикеров. Можно выбрать состав итогов: только краткие буллеты, без итогов или подробные итоги.

Пакет устроен как [iva-file-delivery](https://github.com/mamysh/iva-file-delivery): Agent Plugin в `plugin/`, навык и Eve Extension с инструментом и расписанием. Исходная запись и промежуточные данные остаются в приватной папке Iva. Для распознавания используется Deepgram; итоги составляет модель, выбранная в самой Iva через `MODEL_PROVIDER`. Отдельный ключ LLM для плагина не нужен.

## Статус проверки

- На тестовой записи M4A (25,7 МБ, 26 минут) в v0.2.0 проверены распознавание, автоматические итоги и создание трёх вариантов Word. Сама запись и результаты обработки в репозиторий не входят.
- На VPS владельца 23.09.2026 установлен v0.2.3 в Iva 0.4.7. Фоновая задача на M4A 25,7 МБ завершилась с первой попытки: Word и тезисы приняты Telegram, в Word вошли все 385 реплик, возвращённые Deepgram. Приём этой записи как входящего сообщения Telegram ещё не проверен.
- Атрибуция спикеров и отдельные слова требуют сверки с записью. Имена и сроки, которые нельзя установить, остаются неназванными.

## Требования

Iva 0.4.7 с настроенным `MODEL_PROVIDER`, Node.js 24, `ffprobe` и `ffmpeg`, ключи `DEEPGRAM_API_KEY`, `TELEGRAM_BOT_TOKEN`, переменные `ASSISTANT_DATA_DIR`, `ASSISTANT_VAULT_DIR`, `TELEGRAM_ALLOWED_USER_IDS`. Для файлов больше 20 МБ нужен локальный Telegram Bot API сервер и `TELEGRAM_BOT_API_URL=http://127.0.0.1:8081`. Плагин ограничивает вход 2 ГБ; фактический потолок загрузки зависит от Telegram, свободного диска и провайдеров.

Текущая Iva 0.4.7 отбрасывает документы больше 20 МБ до вызова плагина. Для отправки большого аудио *одним файлом прямо в чат* нужен небольшой патч Iva из [`compat/iva-0.4.7-large-audio.patch`](compat/iva-0.4.7-large-audio.patch). Он передаёт `file_id` только для `.m4a`/`.mp3`, когда включён `IVA_MEETING_LARGE_MEDIA_HANDOFF=1`. Плагин получает файл через локальный Bot API. Для остальных больших вложений прежний порядок сохраняется. На других версиях Iva патч нужно сверить с их кодом.

## Установка на сервере

Сначала сделайте резервную копию работающей сборки Iva и загрузите репозиторий на сервер. Команды ниже приведены для повторной установки или другого сервера. Штатная команда `iva plugin add` создаёт новую версию Iva, поэтому совместимый патч для файлов больше 20 МБ нужно применять **после** установки плагина к новой активной версии.

```bash
git clone --branch v0.2.3 https://github.com/Kotpes537/iva-meeting-transcription.git
```

Плагин использует уже выбранные в Iva модель и доступ к ней. Установите его штатной командой:

```bash
cd /path/to/iva-meeting-transcription
pnpm install --frozen-lockfile
pnpm run check
iva plugin add Kotpes537/iva-meeting-transcription/plugin@v0.2.3
iva plugin list
iva doctor
```

Для больших файлов настройте локальный Telegram Bot API сервер и `TELEGRAM_BOT_API_URL=http://127.0.0.1:8081`. Затем на новой активной версии Iva 0.4.7 проверьте и примените патч:

```bash
cd /path/to/iva/current
git apply --check /path/to/iva-meeting-transcription/compat/iva-0.4.7-large-audio.patch
git apply /path/to/iva-meeting-transcription/compat/iva-0.4.7-large-audio.patch
```

Добавьте `IVA_MEETING_LARGE_MEDIA_HANDOFF=1` в окружение Iva, выполните `npm run build` и перезапустите `iva.service` штатным способом. После любого обновления Iva или кодового плагина этот локальный патч нужно сверить и применить заново: новая версия собирается из исходного кода Iva и не наследует правку предыдущей версии.

`iva plugin add` и сборка могут перезапустить сервис. Используйте штатный порядок обновления вашей Iva. Плагину не нужны отдельный Telegram-бот или второй токен.

Для локальной установки из распакованного архива используйте `iva plugin add /path/to/iva-meeting-transcription/plugin`.

## Использование

Отправьте боту `.m4a` или `.mp3` **документом**. В подписи можно написать:

- `Итоги встречи. Word: краткие буллеты и полная транскрибация.`
- `Расшифруй встречу. Word: только транскрипт.`
- `Итоги и полный транскрипт в одном Word.`

Ива сообщит, что задача принята. После обработки плагин пришлёт Word отдельным файлом и ответит на исходное сообщение тезисами. В каждом режиме Word содержит полный транскрипт. Режим «только транскрипт» убирает итоги из Word; «краткие буллеты» добавляет только основные тезисы; «оба раздела» добавляет подробные итоги. Если саммари не удаётся подготовить, плагин всё равно отправит Word с транскриптом и продолжит попытки получить итоги. Дата берётся из имени файла или метаданных; если данных нет, это будет прямо указано.

Задачи хранятся в `ASSISTANT_DATA_DIR/meeting-transcription/jobs/`. При сбое плагин повторяет обработку до трёх раз; успешные этапы не пересчитываются. Долгие записи обрабатываются по одной.

Команда `pnpm run check` создаёт тестовые Word во временной папке и удаляет их после проверки. Она не отправляет файлы в Telegram. Для просмотра готового документа используйте работу плагина в Iva или скрипт `scripts/probe-report.mjs` с сохранёнными транскриптом и саммари.

Перед распознаванием плагин пытается очистить контейнер аудио от метаданных и обложки, копируя аудиопоток без декодирования и перекодирования. Если очищенный файл не меньше оригинала, параметры потока отличаются или есть дополнительные дорожки с содержимым, используется исходная запись. Качество аудио при этом не меняется, но экономия обычно небольшая: MP3 и AAC в M4A уже сжаты с потерями. На размер файла, который пользователь отправляет в Telegram, серверная очистка не влияет.

## Разработка и ограничения

```bash
pnpm install --frozen-lockfile
pnpm run check
```

Промпт для итогов находится в [`pipeline.ts`](plugin/sh.iva/extension/lib/pipeline.ts). Он требует тайминг для каждого решения, задачи и открытого вопроса, запрещает домысливать участников и сроки. Автоматическая проверка подтверждает наличие тайминга, но не смысловую точность: перед управленческим использованием итоги и реплики нужно сверить с аудио.

Саммари использует выбранную в Iva модель, но по умолчанию снижает усилие рассуждения только для своей фоновой задачи до `low`. Настройка обычного чата при этом не меняется. При необходимости задайте `MEETING_SUMMARY_THINKING_EFFORT=medium`, `high`, `max` или `inherit` для использования общего значения Iva. Плагин ждёт ответ до 10 минут на попытку. Отдельного ключа или модели Gemini в плагине нет.

Word отправляется через обычный Bot API и ограничен 50 МБ. Очень длинный транскрипт может превысить этот размер; тогда задача завершится ошибкой в журнале, пока не будет добавлено разбиение на части. Название файла и текст встречи могут быть конфиденциальными: храните пакет и результаты в закрытом доступе.
